# 工作流程

## 从目标到固定工程

评论旧站故事中的灯。先准确引用原作，分别提出等待与离别两种读法，保留互相质疑的理由。准备一篇评论，改开头后指出哪些主张要重新核对。先检查活动包、专业Schema和当前WorkRef，读取已存在的工程及原操作。读取固定原作和二手材料 → 准确引文 → 提出解释和理由 → 比较不同读法 → 准备评论段落与主张锚点 → 固定意见返工 → 复核依据 → 评论与完整论证本。

## 专业方法

引文固定来源修订及UTF-8字节区间，只追加不可覆盖；原作与二手评论分别标记。每个解释保留适用范围、引文和推理理由。关系区分支持、质疑和限定，允许多种解释共存，不把图可达性、支持数量或循环当逻辑真理。文章主张固定段落摘要、准确选区和所用解释组合摘要；段落、相关解释或关系变化后待复核，旧锚点绝不定位到新稿。新建或主动调整锚点必须匹配当前原文和依据；已有过期记录可保留历史。局部备选固定整个段落摘要，应用后旧主张与意见过期，其他段落字节保持。

故事分析诊断叙事结构，本包创作独立评论文章；纪实核实主张的事实依据，本包保留解释及竞争读法，不认证评论的唯一正确性、学术原创性或引用权利。没有独立资料抓取、查重服务或作者联系功能。无材料时明确缺口，不伪造来源。摘录必须从固定原文取得UTF-8区间，quote_context／get_source分块不等于已读完整原作。

## 返工与交付

先回读具体意见的目标摘要，检查过期；准备备选并比较理由，使用后读取影响报告，按作者意图修订依据。保留未修改内容，不自动重签所有快照。以完整JSON保存专业结构，阅读本供连贯审阅；分块重组后核对完整摘要。

同作品跨包接续固定Owner、对象、revision和sha256，独立剧本与视频各自发现管理能力。下一稿通过实际发现的宿主候选入口准备，专业保存不代表正文采纳。

## 进入作品下一稿

本次目标需要宿主下一稿时，先create_handoff并回读确切专业修订。BasisRef不是宿主任务SourceRef，不能直接混传。通过实际发现的资料任务保存只读派生接续快照：保留专业Owner、对象、revision、sha256、包摘要和实际专业内容，专业事实仍由原插件拥有。再用原材料和快照的固定resource来源准备相应创作任务，回读task_context目录及完整原字节，提交真正的参考稿并回读。没有指定正文目标时不要按名称猜章节；参考稿不等于正文采纳或定稿。
