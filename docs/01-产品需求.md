# 产品需求

## 背景与推导

文学评论既需要准确引文，也需要保留解释的开放性。同一句话可以支持不同读法，引用正确不等于解释成立；文章改写后，旧论据也可能不再支撑原段落。Agent负责提出与比较解释，软件保存原作、引文、推理理由、关系和文章锚点，让作者看到论证的实际边界。

生成成本和等待时间会变化，但固定作品、历史依据、具体意见与连续审阅仍需长期积累。固定工程避免让模型每轮重建结构；结构化数据与多种阅读方式共用同一专业成果。插件按需安装，让作者提出目标、Agent操作工程、作者在适合的工作面阅读和选择。

## 定义与首版

文学评论是河图洛书JS／TS专业插件。把原作引文、解释理由、不同读法与评论文章联系起来，让每次改稿都能回到依据。用户包括独立作者、编辑与外部Agent。默认旅程：读取固定原作和二手材料 → 准确引文 → 提出解释和理由 → 比较不同读法 → 准备评论段落与主张锚点 → 固定意见返工 → 复核依据 → 评论与完整论证本。

首版包含完整专业维护、准确来源回读、并行方案、局部备选、意见、改稿影响、上下文、固定交接、JSON／Markdown／HTML工程及专业阅读本。功能必须经机器入口执行，作者可以自然语言提出目标，也保留人工优化入口。

## 边界

故事分析诊断叙事结构，本包创作独立评论文章；纪实核实主张的事实依据，本包保留解释及竞争读法，不认证评论的唯一正确性、学术原创性或引用权利。没有独立资料抓取、查重服务或作者联系功能。正文、正式设定、素材、采纳与定稿由宿主和作者掌握，不另建数据库、模型渠道或内部Agent。

成功以真实创作、审阅、返工及下一轮接续为准，安装、动作数或文件存在都不足以代表完成。开发与验收状态只由08维护。
