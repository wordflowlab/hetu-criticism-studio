# Skill与机器接续

包内hetu-criticism-studio由河图动态发现，不创建Codex插件、独立MCP服务器或客户端工具名。安装和启用后重新读取活动包摘要、capabilities与skills.read；旧能力绑定不得继续使用。业务无需启动桌面。

默认旅程：读取固定原作和二手材料 → 准确引文 → 提出解释和理由 → 比较不同读法 → 准备评论段落与主张锚点 → 固定意见返工 → 复核依据 → 评论与完整论证本。先读已有工程、固定作品及意见，不新建另一份演示工程替代接续。方法由Skill维护，确定性规则由专业后端执行。

引文固定来源修订及UTF-8字节区间，只追加不可覆盖；原作与二手评论分别标记。每个解释保留适用范围、引文和推理理由。关系区分支持、质疑和限定，允许多种解释共存，不把图可达性、支持数量或循环当逻辑真理。文章主张固定段落摘要、准确选区和所用解释组合摘要；段落、相关解释或关系变化后待复核，旧锚点绝不定位到新稿。新建或主动调整锚点必须匹配当前原文和依据；已有过期记录可保留历史。局部备选固定整个段落摘要，应用后旧主张与意见过期，其他段落字节保持。

每阶段保存并回读固定修订，create_handoff记录依据、目标与未解决问题。其他插件根据实际安装能力独立发现，通过固定专业引用组合。未知先回读，正文采纳、定稿、内容外发与费用按作者确切决定执行。

SKILL.md作为精炼方法入口，references/workflows.md提供专业方法与反例，operations.md从正式清单生成。专业清单由本仓库维护，宿主40只导航动态入口。

## 专业成果进入下一稿

专业BasisRef与宿主任务SourceRef各有语义，不能混传。Agent先读取固定专业工程与实际依据，经公开资料任务保存派生接续快照，在快照中保留Owner、对象、修订、包摘要和完整来源；原专业工程仍为事实Owner。下一稿任务同时固定原材料和派生快照，回读真实任务目录及完整字节后再提交章节参考稿，不以空输入任务或一段泛化提示证明接续。
